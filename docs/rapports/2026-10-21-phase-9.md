## Bascule

Le port 8089 sert `fcc_001_web` (Nginx + build React). `/api` est proxifié vers `fcc_001_api`, sur le réseau du MariaDB réel. Les volumes `fcc_001_app_uploads` et `fcc_001_app_instance` sont les mêmes que Flask. Les avatars ont été copiés dans `fcc_001_app_avatars` (8 fichiers) et sont servis sous `/static/avatars/`. L’API tourne avec l’uid 1000, le même que l’utilisateur Flask, pour que les fichiers créés restent lisibles au retour arrière.

`PASSWORD_REHASH` est faux. Les cookies ne sont pas `Secure` (HTTP local). `WEB_ORIGIN` accepte `localhost` et `127.0.0.1` sur le port 8089.

Commande :

```bash
docker compose -p fcc_001 -f docker-compose.yml -f docker-compose.bascule.yml up -d api web
```

Contrôles après démarrage : page de login React, CSS Flask, bundle, avatar, `GET /api/health` 200, `GET /api/clients` 401, login d’un compte absent 401 « Credenciales incorrectas », `/incidencias` sans cookie revient au login.

Retour arrière :

```bash
docker compose -p fcc_001 -f docker-compose.yml -f docker-compose.bascule.yml stop web api
docker update --restart=unless-stopped fcc_001_app
docker start fcc_001_app
```

Le profil `with-nginx` du compose principal pointe encore vers Flask. Ne pas l’activer pendant la fenêtre. Le code Flask n’est pas retiré : c’est l’étape d’après les 48 h.
