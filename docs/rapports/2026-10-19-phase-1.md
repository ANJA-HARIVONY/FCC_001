# Rapport — phase 1, authentification

Date : 19 octobre 2026. Branche : `feat/reecriture-react-node`.

## Ce qui est fait

Le schéma Prisma est le reflet de MariaDB (`prisma db pull`, 18 modèles). Aucune migration n'a été appliquée. Les noms de colonnes françaises sont inchangés.

L'API `@fcc/api` (NestJS, port 4000) expose :

| Méthode | Chemin | Rôle |
|---|---|---|
| GET | `/api/health` | santé, public |
| GET | `/api/auth/csrf` | cookie `fcc_csrf` non HttpOnly + jeton |
| POST | `/api/auth/login` | email, téléphone ou nom unique ; cookie `fcc_session` HttpOnly |
| POST | `/api/auth/logout` | fin de session |
| GET | `/api/auth/me` | utilisateur courant, sans hash |
| POST | `/api/session/ping` | repousse l'inactivité |

La session vit en mémoire du processus : 12 h absolues, 30 min d'inactivité, audit `LOGOUT_IDLE_TIMEOUT`. Pas de table `session` et pas de Redis, donc aucun `ALTER`. Le cookie `Secure` ne s'active que si `SESSION_COOKIE_SECURE=true`.

Les mutations exigent l'en-tête `X-CSRFToken`. Un `next` hors du même hôte est ignoré. Les en-têtes CSP, `nosniff`, `SAMEORIGIN` et Referrer-Policy sont posés. Les journaux masquent mot de passe, cookie et URI MySQL.

Le vérificateur accepte les hash Werkzeug `scrypt:32768:8:1$sel$hex`, contrôlé contre un hash produit par le conteneur Flask (mot de passe synthétique, pas un compte réel). Argon2id n'est écrit que si `PASSWORD_REHASH=true`. La valeur par défaut est `false` : Flask partage encore la base et ne saurait plus lire un hash Argon2.

L'audit (`LOGIN`, `LOGOUT`, `LOGOUT_IDLE_TIMEOUT`) est best-effort. Un compte `actif=false` reçoit « Cuenta desactivada. ». Un hash vide reçoit le message administrateur.

`docker-compose.rewrite.yml` branche l'API sur le réseau MariaDB existant, sans remplacer le Flask. L'image n'a pas été construite dans ce lot.

## Vérification


Le test HTTP couvre le cookie de session, le refus sans CSRF, l'en-tête `nosniff` et le rejet après 30 minutes d'inactivité, avec une horloge injectée.
